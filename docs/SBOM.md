# Release SBOM profile

Starting with v0.14.0, each release bundle includes a deterministic SPDX 3.0.1 JSON-LD graph
and a schema-version-2 AWQ manifest. Historical schema-version-1 manifests remain readable;
a release at v0.14.0 or later cannot pass bundle verification without its SBOM.

## Inventory and claims

The canonical inventory in config/release-licenses.json covers the root MIT-licensed package,
every development package in uv.lock, and every package in the hash-pinned build constraints.
Pathspec has both development and build scope. Dependency scopes use SPDX lifecycle-scoped
relationships. Package records name exact versions and package URLs; locked development packages
also retain their exact public source-archive download origin and checksum. Supplier identities
are not inferred from registry hosting. Build-archive hashes identify allowed inputs, not a claim
that every permitted archive was installed.

The root has zero third-party runtime package dependencies. This is checked against project and
lock metadata and against the wheel's dependency metadata during release verification. Development
and build packages are not represented as contained in the wheel. The schema container is bundled
data, not a Python dependency. Python itself, the operating system and separately acquired adapter
tool bundles are external, so this is not a complete workstation or deployed-system inventory.

License expressions are reviewed package metadata, not a legal opinion, compatibility conclusion
or exhaustive file-level copyright assessment. The root package's MIT declaration does not
relicense upstream schema material. Preserve its upstream notices below.

## Determinism and verification

The namespace binds the public source commit and release version. Creation time comes only from
the Git source epoch, never the wall clock. Identifiers, ordering and JSON bytes are deterministic.
The graph binds wheel/source identities and hashes, uv.lock, build constraints, the license
inventory, root LICENSE, project metadata and the exact schema container. The manifest additionally
binds the SBOM bytes, media type, profile, specification edition and authoritative schema digest.

Offline bundle verification reads bounded regular inventory files from the already-verified source
archive, regenerates the exact graph and rejects any difference. This is a narrow manual semantic
profile, not a general-purpose SPDX parser. Unknown fields, omitted packages, changed licenses,
scopes, origins, relationships or identifiers fail closed. Canonical JSON, duplicate-key, byte-bound
and private-content checks also apply. No JSON-LD context or remote schema is fetched at runtime.

CI separately validates the generated graph using the pinned official JSON Schema and the existing
locked development-only jsonschema dependency. Passing these checks is not SPDX certification,
publisher authentication, legal compliance or proof of dependency safety.

Use the existing offline command; the complete bundle must remain together:

    awq release-verify /new/external/release/agent_workflow_quality-0.14.0.release.json --format json

Regenerate the synthetic public contract fixture after intentional input changes:

    uv run python scripts/generate_sbom_fixture.py
    uv run python scripts/generate_sbom_fixture.py --check

The fixture uses synthetic source and artifact identities. It is not release evidence. Real bundles
are generated by scripts/build_release.py from the clean signed source and real artifacts.

The exact authoritative bytes were retrieved anonymously on 2026-09-09 from the
[official SPDX 3.0.1 JSON Schema](https://spdx.org/schema/3.0.1/spdx-json-schema.json).

    582c64e809d5b3ef9bd0c4de13a32391b47b0284a3e8d199569fb96f649234b1

The original JSON uses CRLF. A deterministic single-entry container,
schemas/spdx-3.0.1.schema.zip, preserves those bytes without exempting ordinary project text
from LF checks. The loader checks the member name, bounds and original digest before schema use.
No upstream Git revision is asserted: attribution binds the canonical URL, edition and exact bytes.
